# BindB 설계 점검 (2026-11-06)

공식 문서와 경쟁 도구를 기준으로 현재 코드의 설계 결정을 다시 점검한 결과입니다. 코드는 아직 고치지 않았습니다.
판정에 쓴 출처는 각 항목에 붙였고, 출처를 확인하지 못한 것은 "확인 못 한 것"에 따로 모았습니다.

## 1순위: 데이터 손실·손상

1. **SQLite 저장 방식** (`src/drivers/sqlite.ts`)
   - 파일 전체를 메모리에 올렸다가(deserialize) 통째로 다시 씁니다(임시 파일 + rename).
   - 다른 프로세스(앱)가 같은 파일을 쓰고 있으면 그 변경이 경고 없이 사라집니다.
   - 열린 파일을 rename으로 바꿔치기하면 저널 파일과 어긋나 DB가 손상될 수 있습니다. SQLite 공식 문서가 손상 원인으로 드는 패턴입니다.
   - WAL 모드에서는 `-wal` 파일에만 있는 최근 커밋이 보이지 않습니다.
   - 같은 WASM 구조를 쓰는 SQLite Viewer 확장은 일부러 읽기 전용으로만 지원합니다.
   - 출처: https://www.sqlite.org/howtocorrupt.html , https://sqlite.org/c3ref/deserialize.html , https://github.com/qwtel/sqlite-viewer-vscode , https://github.com/qwtel/sqlite-viewer-vscode/discussions/55
2. **PostgreSQL·H2 날짜 처리** (`src/drivers/postgres.ts`, `src/ui/resultPanel.ts:389`, `src/core/editing.ts`)
   - node-postgres는 `date`/`timestamp`를 Node 프로세스의 로컬 시간대로 JS `Date`에 담습니다. BindB는 이를 UTC ISO 문자열로 바꿉니다.
   - UTC+9에서 `2024-01-01`은 `2023-12-31T15:00:00.000Z`가 됩니다. 날짜가 키인 행을 수정·삭제하면 **다른 행이 바뀔 수 있습니다.**
   - 마이크로초와 시간대가 사라져 그리드, 복사, 내보내기 값도 틀립니다.
   - MySQL은 `dateStrings: true`라 영향이 없습니다.
   - 출처: https://node-postgres.com/features/types
3. **H2 접속 방식** (`src/drivers/h2.ts`)
   - H2의 PG 서버를 거칩니다. 이 서버는 `MODE=PostgreSQL`, `DATABASE_TO_LOWER=TRUE`, `DEFAULT_NULL_ORDERING=HIGH`를 고정으로 걸고, 끄는 옵션이 없습니다(`PgServerThread.java:271-276`).
   - Java 앱이 만든 DB는 테이블 이름이 대문자로 남습니다. 그래서 따옴표 없는 조회는 실패하고 BindB에서는 비어 보입니다.
   - DB 이름 뒤에 `;DATABASE_TO_LOWER=FALSE`를 붙이면 `DUPLICATE_PROPERTY` 오류로 접속 자체가 실패합니다(`ConnectionInfo.java:314-338`).
   - H2를 지원하는 도구(DataGrip, DBeaver, Harlequin)는 모두 JDBC로 직접 접속합니다.
   - 출처: https://github.com/h2database/h2database (tag version-2.5.252), https://www.jetbrains.com/help/datagrip/h2.html , https://pypi.org/project/harlequin-h2/ , https://groups.google.com/g/h2-database/c/QZKNDxNJ5kA

- 1번(SQLite) 조사:
  - VS Code 1.103부터 Node 22.17이 들어 있습니다(https://code.visualstudio.com/updates/v1_103).
  - `node:sqlite`는 v22.5.0에 추가됐고, v22.13.0부터 플래그 없이 쓸 수 있습니다. 실제 파일, `readOnly`, `timeout`(v22.16.0), `setAuthorizer`(v24.10.0)를 지원합니다(https://nodejs.org/api/sqlite.html).
  - FTS5는 Node PR #57621에서 켜졌습니다(https://github.com/nodejs/node/pull/57621). 이 기기의 VS Code(Node 24.22.1, SQLite 3.53.4)에서 실제로 확인했습니다.
  - 공식 sqlite-wasm 패키지에서 Node용 실제 파일 VFS(잠금 포함)는 찾지 못했습니다.
- 1번(SQLite) 고침:
  - `node:sqlite`(DatabaseSync)로 실제 파일을 엽니다. busy timeout은 5초입니다.
  - 읽기 전용 연결과 AI 조회는 `readOnly: true`로 엽니다. 따라서 SQLite가 쓰기를 거부합니다.
  - 여러 문장을 한 번에 보내면 거부합니다. `prepare`가 첫 문장만 컴파일하고 나머지를 버리기 때문입니다.
  - 정수는 정밀도를 지킵니다(BigInt).
  - `engines.vscode`를 `^1.103.0`으로 올리고, sqlite-wasm 의존성을 지웠습니다.
  - 확인:
    - 단위 테스트 90개가 통과했습니다. 다른 연결이 쓰는 WAL DB를 함께 써도 서로의 변경이 남고, 읽기 전용에서는 `PRAGMA x(1)`이 거부됩니다.
    - 통합 테스트 20개가 VS Code stable과 1.103.0에서 모두 통과했습니다.
    - 1.103.0 런타임(Node 22.17.0, SQLite 3.50.0)에서 FTS5 동작을 확인했습니다.
  - 남은 점: 1.103.0에서는 `node:sqlite`가 아직 실험 기능이라 ExperimentalWarning이 출력됩니다.
- 서브에이전트 검수 후 고친 것:
  - 결과를 열어 둔 동안 읽기 잠금이 남아 다른 앱의 쓰기가 막혔습니다. 이제 결과를 실행할 때 끝까지 읽습니다(큰 결과는 메모리를 씁니다).
  - `INSERT … RETURNING`이 첫 행을 읽을 때에야 실행됐습니다. 이제 실행 시점에 돌고, 영향받은 행 수는 `changes()`로 구합니다(https://www.sqlite.org/lang_corefunc.html).
  - 매개변수 처리: boolean과 undefined는 SQLite가 받는 값으로 바꾸고, 객체는 거부합니다. 객체를 그대로 넘기면 이름 있는 매개변수로 해석돼 나머지 값이 밀립니다.
  - THIRD_PARTY_NOTICES를 다시 만들었습니다.
  - 확인: 단위 93개, 통합 20개(stable, 1.103.0) 모두 통과했습니다.
- SQLite 별도 프로세스(src/drivers/sqliteHost.ts):
  - 실행 위치: `node:sqlite`는 동기 API라 확장 호스트에서 돌리면 멈춥니다. 그래서 fork로 띄운 자식 프로세스에서 돌립니다. 방식은 VS Code 언어 서버 클라이언트와 같은 `ELECTRON_RUN_AS_NODE=1`입니다.
  - 취소: 자식 프로세스를 SIGKILL로 끝냅니다.
    - worker_threads의 `terminate()`는 실행 중인 쿼리가 끝날 때까지(실측 36초) 돌아오지 않았습니다.
    - 도중에 끝나도 SQLite가 저널로 되돌립니다(https://www.sqlite.org/atomiccommit.html). 테스트로 무결성과 되돌림을 확인했습니다.
  - 결과: 10만 행까지는 자식 프로세스에서 미리 읽어 잠금을 바로 풀고, 넘는 부분은 요청할 때 읽습니다.
  - 닫기: 쿼리가 도는 중에 닫으면 즉시 끝냅니다. `error` 이벤트를 처리하고, 확장을 끌 때(deactivate) 자식 프로세스를 모두 끝냅니다.
- 토크나이저를 DB 종류별 규칙으로 바꿨습니다(4번 일부).
  - DB별 규칙:
    - PostgreSQL: E'…'에서만 백슬래시 이스케이프, `#`은 연산자, 중첩 주석
    - MySQL: `#` 주석, `-- ` 뒤 공백, `"…"` 문자열, `/*! */`는 코드
    - SQLite: 백슬래시 이스케이프 없음
    - H2: `//` 주석, 중첩 주석, `$$`
  - 적용한 곳: 실행, 전체 실행, CodeLens, 자동 완성, DDL 파싱, 그리드 필터, 시작 스크립트, 분류기
- 분류기 보강:
  - 따옴표로 감싼 함수 이름도 위험 함수로 판정합니다.
  - SQLite PRAGMA 판정: 공식 문서에 나온 읽기 전용 목록과 쓰기 목록을 따릅니다.
  - `FOR NO KEY UPDATE` · `FOR KEY SHARE`, `LOCK IN SHARE MODE`, `EXPLAIN ANALYZE … INTO`를 쓰기로 판정합니다.
- 문장 맨 앞의 `BEGIN …`(IMMEDIATE, ISOLATION LEVEL 등)을 트랜잭션으로 봅니다.
- 확인:
  - 단위 110개, 통합 21개(stable, 1.103.0) 모두 통과했습니다.
  - 테스트가 끝난 뒤 남은 sqliteHost 프로세스가 0개입니다.
  - VSIX에 `out/sqliteHost.js`가 들어 있습니다.

### 4순위 고침 (2026-11-09) — 사용자 결정: 지우지 않고 DataGrip에 맞춘다

출처: https://www.jetbrains.com/help/datagrip/data-sources-and-drivers-dialog.html , https://www.jetbrains.com/help/datagrip/introspection-levels.html

- Auto sync: 0.2.0에서 이미 동작(DDL을 실행하면 다시 읽음). 확인만.
- 구조 정보 수준: 기본을 자동(DataGrip 표의 객체 수 기준)으로, 스키마마다 지정(탐색기), 1단계는 열 이름까지(타입 없음). 실제 PG에서 1001개 스키마로 경계 확인.
- Load sources for: DataGrip도 2단계는 소스를 읽지 않으므로 같은 동작. 그대로.
- 세션 템플릿: Authentication · Driver 추가, 읽기 전용 끄기, 시작 스크립트 대체. 그리드 편집 · AI 쓰기도 템플릿의 읽기 전용을 따른다(전에는 원래 값만 봤다).
- Dedicated sessions: 콘솔마다 세션, 구조 정보 읽기용 세션 따로 — DataGrip과 같다(코드 확인).
- keep-alive 쿼리: 바꿀 수 있게(읽기 문장 하나만).
- 읽기 전용이 드라이버마다 다름: DataGrip 문서도 드라이버가 지원하지 않으면 콘솔에서 바뀔 수 있다고 적는다. BindB는 실행 전 판정 + PG · MySQL은 DB 설정 + SQLite는 읽기 전용 열기. H2는 드라이버 안의 중복 판정을 빼고 SessionManager 판정으로 지킨다(시작 스크립트의 SET이 막히던 문제).
- URL 편집: prefer는 고침(2순위 13번). JDBC 템플릿 대신 각 드라이버의 URL을 쓰는 것은 그대로(Node 드라이버라서).
- 트랜잭션 격리 수준: 추가(PG · MySQL은 세션 설정 문장, H2는 JDBC setTransactionIsolation).
- DataGrip에 없는 항목: Connect timeout · 코드 스타일 드롭다운 · SSL Mode는 쓸모가 있어 둔다. General 탭의 H2 jar는 원격에도 필요해져서 둔다. "Copy from"은 DataGrip처럼 SSH만 복사하게 고쳤다.
- 빠진 항목: Create database(H2 Embedded) · Introspect using JDBC metadata(H2, 1.x는 자동) 추가. IDE Passwords Settings는 VS Code에 해당 설정이 없어 Save 옆 설명으로. Warn when editing outdated DDL은 BindB에 객체 DDL 편집 기능이 없어 넣지 않았다(그 기능을 만들 때 함께).

### 3번 고침 (2026-11-09)

- DataGrip처럼 JDBC 드라이버를 별도 JVM에서 돌리는 내부 모듈을 만들었습니다(`java/bridge` · `src/drivers/jdbc`). 표준 입출력의 JSON 줄로 주고받고, 첫 연결 때 띄워 마지막 연결이 닫히면 끕니다. jar는 14KB이고 `npm run build:java`(JDK 필요)로 다시 만들어 커밋합니다.
  - 출처: https://www.jetbrains.com/help/datagrip/data-sources-and-drivers-dialog.html (드라이버는 별도 프로세스의 JVM에서 실행), https://www.jetbrains.com/help/datagrip/h2.html
- H2는 Embedded · Remote(TCP) · URL only로 직접 붙습니다. Java 앱이 만든 DB(PUBLIC), PG 모드로 만든 예전 DB(재시도), 1.4 `.h2.db`(1.4 jar, MV_STORE=FALSE)를 실제로 열어 확인했습니다. 페이지 단위 읽기 · 취소도 됩니다.
- 남은 점: 사용자에게 Java 11 이상이 필요합니다(DataGrip은 JBR을 함께 배포). H2 배열은 H2가 주는 글자(`[a, b]`)로 보이고, 그 글자를 그대로 다시 저장하면 원소 하나짜리 배열(`[[a, b]]`)이 됩니다(실측). 그래서 H2의 배열 열은 그리드에서 편집하지 않게 했습니다.

## 2순위: 보안

4. **AI 읽기 전용 판별 우회** (`src/core/classify.ts`, `tokenizer.ts`)
   - 따옴표로 감싼 함수 이름은 위험 함수 목록 검사를 건너뜁니다. H2에서는 `"FILE_WRITE"`, `"CSVWRITE"`가 통과합니다.
   - SQLite `PRAGMA x(1)`은 `PRAGMA x = 1`과 같은 동작인데 읽기로 분류됩니다.
   - PostgreSQL에서 `#`은 XOR 연산자인데 주석으로 처리됩니다.
   - MySQL 실행 주석 `/*! … */`의 내용(`INTO OUTFILE` 등)을 무시합니다.
   - 모든 DB에서 백슬래시 이스케이프를 가정합니다.
   - SQLite와 H2는 DB 차원의 읽기 전용 보호 없이 이 분류기 하나에만 의존합니다.
   - 분류기만 믿는 방식은 레퍼런스 Postgres MCP 서버가 실제로 뚫린 방식입니다. 권장 방식은 DB가 강제하는 읽기 전용(읽기 전용 트랜잭션·역할, SQLite 읽기 전용 열기, H2 `ACCESS_MODE_DATA=r`)을 겹쳐 쓰는 것입니다.
   - 출처: https://securitylabs.datadoghq.com/articles/mcp-vulnerability-case-study-SQL-injection-in-the-postgresql-mcp-server.md , https://www.sqlite.org/pragma.html
5. **`bindb.ai.allowWrites` 설정 범위** (`package.json`)
   - 범위 지정이 없어 기본값 `window`가 됩니다. 저장소의 `.vscode/settings.json`으로 AI 쓰기를 켤 수 있습니다.
   - `application` 또는 `machine`으로 바꿔야 합니다.
   - 출처: https://code.visualstudio.com/api/references/contribution-points
6. **MCP 서버 Origin 검사 없음** (`src/ai/mcpServer.ts:229-238`)
   - MCP 명세는 Streamable HTTP 서버가 `Origin`을 반드시 검사하라고 합니다(MUST). 토큰이 있어 실제 위험은 낮습니다.
   - 출처: https://modelcontextprotocol.io/specification/2025-06-18/basic/transports
7. **연결 비밀번호를 연결 id 하나로 저장** (`src/core/connections.ts:10`)
   - 프로젝트 설정에 전역 연결과 같은 id로 다른 호스트를 넣으면, 전역 연결의 비밀번호가 그 호스트로 갑니다. `ssh.configId`도 같습니다.
   - Workspace Trust의 restrictedConfigurations는 제한 모드에서만 막고, 신뢰한 작업 공간은 막지 않습니다.
   - id가 무작위 UUID라 공격자가 id를 알아야 합니다.
   - 출처: https://code.visualstudio.com/api/extension-guides/workspace-trust
8. **Claude Code·Codex 등록** (`src/ai/integration.ts`)
   - `$(cat …)`로 넘긴 토큰이 프로세스 인자(`ps`)에 보입니다.
   - 이 명령은 POSIX 전용이라 PowerShell에서 동작하지 않습니다.
   - "Copy Command"만 하고 실행하지 않으면 토큰이 든 임시 파일이 남습니다.
   - Codex는 `bearer_token_env_var`를 쓰면 평문 토큰을 저장하지 않아도 됩니다.
   - 출처: https://learn.chatgpt.com/docs/extend/mcp?surface=cli

## 3순위: 실제 DB에서 깨지는 기능

9. **PostgreSQL 구조 정보를 information_schema로 읽음** (`src/drivers/infoSchema.ts`)
   - 머티리얼라이즈드 뷰가 보이지 않습니다.
   - 권한이 없는 객체는 빠지고, 뷰 정의는 소유자가 아니면 비어 나옵니다.
   - 기본 키가 빠지면 그리드 편집을 할 수 없습니다.
   - 출처: https://www.postgresql.org/docs/current/infoschema-tables.html , https://www.postgresql.org/docs/current/infoschema-views.html
10. **스키마 전환** (`src/core/sessions.ts:531`): `SET search_path TO "x"`가 `public`을 빼 버려서 PostGIS, uuid 같은 확장 객체를 찾지 못합니다.
    - 출처: https://www.postgresql.org/docs/current/ddl-schemas.html
11. **수동 트랜잭션 모드** (`src/core/sessions.ts:219-223`)
    - 모든 문장 앞에 `BEGIN`을 붙여서 `VACUUM`, `CREATE INDEX CONCURRENTLY`가 실패합니다.
    - 오류 뒤에도 `inTx` 상태가 남아 이후 문장이 모두 실패합니다.
12. **쿼리 취소** (`src/drivers/postgres.ts:93-103`)
    - 새로 로그인한 뒤 `pg_cancel_backend`를 부릅니다. 권한이나 연결 수 제한, PgBouncer 환경에서 실패할 수 있습니다.
    - 표준은 프로토콜의 CancelRequest입니다.
    - 출처: https://www.postgresql.org/docs/current/functions-admin.html
13. **sslmode 매핑** (`src/core/connectionDraft.ts:441-443`, `src/drivers/common.ts:69-90`)
    - `prefer`를 `require`로 바꿔서 SSL이 없는 서버에 접속하지 못합니다.
    - `verify-ca`가 없습니다.
    - CA 파일을 주고 `require`를 고르면 검증을 하지 않습니다(libpq는 이 경우 `verify-ca`처럼 동작).
    - 출처: https://www.postgresql.org/docs/current/libpq-ssl.html , https://nodejs.org/api/tls.html
14. **MySQL 읽기 전용**
    - 임시 테이블 DML이 허용됩니다.
    - 세션에서 `READ WRITE`로 되돌릴 수 있습니다.
    - 결국 분류기에 의존합니다.
    - 출처: https://dev.mysql.com/doc/refman/8.0/en/set-transaction.html
15. **SSH** (`src/drivers/tunnel.ts`, `src/drivers/sshHosts.ts`)
    - Windows에서 `SSH_AUTH_SOCK`이 없으면 에이전트 인증이 항상 실패합니다. Pageant나 OpenSSH 파이프로 대신 시도하지 않습니다.
    - ssh_config에서 다음을 지원하지 않습니다.
      - `Include`
      - `Match`(블록 전체를 건너뜀)
      - `ProxyJump`/`ProxyCommand`
      - 여러 `IdentityFile`(첫 번째만 씀)
      - 기본 키 파일
      - `%h` 외의 토큰
    - keyboard-interactive와 2FA 인증이 없습니다(`tryKeyboard` 미설정).
    - 출처: https://man.openbsd.org/ssh_config.5 , https://github.com/mscdex/ssh2
16. **known_hosts** (`src/drivers/sshHosts.ts:61-91`)
    - 부정 패턴(`!host`)을 무시합니다.
    - `@cert-authority`를 무시합니다.
    - 키 종류가 달라도 "키 변경"으로 거부합니다.
    - `/etc/ssh/ssh_known_hosts`를 읽지 않습니다.
    - 출처: https://man.openbsd.org/sshd.8
17. **필터·정렬 줄의 서브쿼리 감싸기** (`src/core/gridQuery.ts`)
    - MySQL에서 열 이름이 중복된 JOIN이 실패합니다.
    - 데이터를 바꾸는 CTE는 실패하고, 새로 고칠 때마다 다시 실행됩니다.
    - 출처: https://dev.mysql.com/doc/refman/8.0/en/derived-tables.html , https://www.postgresql.org/docs/current/queries-with.html
18. **SQL INSERT 내보내기** (`src/shared/exportFormats.ts:119`): MySQL `NO_BACKSLASH_ESCAPES` 모드를 무시해서 값이 바뀝니다.
    - 출처: https://dev.mysql.com/doc/refman/8.0/en/string-literals.html
19. **H2 버전과 파일 형식**
    - jar 버전과 파일 형식(1.4 ↔ 2.x)을 맞추지 않습니다.
    - `.h2.db` 파일을 열지 못합니다.
    - 다운로드는 같은 서버의 SHA-1로만 확인합니다(PGP 서명은 확인하지 않음).
    - 출처: https://confluence.atlassian.com/bitbucketserver094/migrate-h2-database-1489803143.html
20. **NULL과 빈 문자열을 복사·붙여넣기할 때 구분이 사라짐** (`webview/grid/main.tsx:252`)

## 4순위: DataGrip과 다르거나 지어낸 것

출처: https://www.jetbrains.com/help/datagrip/data-sources-and-drivers-dialog.html , https://www.jetbrains.com/help/datagrip/introspection-levels.html

- **동작하지 않음:** "Auto sync"는 저장만 되고 읽는 코드가 없습니다.
- **동작이 다름:**
  - 구조 정보 읽기 수준: DataGrip은 스키마 크기에 따라 자동으로 정하고 스키마마다 바꿀 수 있습니다. BindB는 연결 전체에 고정값 하나(기본 3)를 쓰고, 1단계에서는 열을 아예 읽지 않습니다.
  - "Load sources for"는 3단계에서만 적용됩니다.
  - 세션 템플릿: Authentication과 Driver가 없고, 읽기 전용을 끌 수 없으며, 시작 스크립트를 대체하지 않고 덧붙입니다.
  - Dedicated 세션 동작이 DataGrip과 같은지 확인하지 못했습니다.
  - keep-alive 쿼리가 `SELECT 1`로 고정되어 있습니다.
  - 읽기 전용이 드라이버마다 다르게 동작합니다.
  - URL 편집이 다릅니다. JDBC 템플릿이 아니고, `prefer`를 `require`로 올립니다.
  - 트랜잭션 격리 수준을 고를 수 없습니다.
- **DataGrip에 없는 항목:**
  - Connect timeout
  - General 탭의 H2 jar
  - 코드 스타일 드롭다운 2개
  - SSL Mode 목록
  - "Copy from" 위치와 범위
- **빠진 항목:**
  - Warn when editing outdated DDL
  - Create database
  - Introspect using JDBC metadata
  - IDE Passwords Settings

## 확인 못 한 것

- DataGrip 스키마 패턴 문법 전체
- DataGrip의 ProxyJump 지원(포럼 검색 결과뿐)
- MySQL에서 같은 값으로 저장하면 영향받은 행 수가 0이 되는지(`CLIENT_FOUND_ROWS`)
- H2 PG 서버가 한 메시지 안의 여러 문장을 실행하는지
- MySQL `CALL`의 다중 결과 집합 처리
- DBCode의 H2 접속 방식(공식 문서 404)
